# 商品登録スキル v2(MORU LIVING)

> v2(2026-08-23)。**v1 の「リファレンスシート生成方式」は廃止した。**
> 廃止理由: 評価 5/10。生成モデルが商品の形状そのものを創作してしまう構造的問題があり、
> 実物と違う商品画像が出荷される危険があった。

## 正の所在(迷ったらここへ戻る)

| 何の正か | どこ |
|---|---|
| **商品の形状・寸法・素材** | **常に実物写真と仕入れ元の実測資料。** 生成物は正になり得ない |
| **ブランドの見え方** | `docs/brand/reference-sheets/`(シート01〜05) |
| ブランド定義・トーン | `docs/00_brand_master.md` v0.2 追補 / `docs/01_brand_guidelines.md` |
| カテゴリ・タグ | `docs/09_navigation_taxonomy.md` |
| アングル | `docs/brand/reference-sheets/04_category_angles.md` |

---

## 鉄則(破らない)

1. **価格設定が完了するまで商品を ACTIVE にしない。** DRAFT で作る
2. **形状・サイズを変える生成をしない。** 商品ピクセルは極力触らない
3. **未確認の品質表現を書かない** —「無垢材」「丸洗い可能」「完全防水」「一生使える」等
   (`docs/01` §7 / `docs/00` 第5章)
4. 「ドロップシッピング」「仕入れ元」を顧客向けに出さない。**配送目安は隠さず明示する**
5. **偽の希少性を作らない**(偽カウントダウン・偽在庫・実績なき二重価格)
6. 寸法・素材の数値は**仕入れ元の実値のみ。** 推定値を図や本文に書かない

## ワークフロー

### 1. Shopify から商品を取得

Shopify MCP の `get-product` / `search_products`、または `graphql_query` で
`id` / `handle` / `title` / `status` / `tags` / `descriptionHtml` / `media` を取る。

### 2. `ops/products/` と照合

```
ops/products/{ナビ分類スラッグ}-{商品スラッグ}/
```

`{ナビ分類スラッグ}` は `docs/09` §1 の6分類(`pet` / `chair-stool` / `table` /
`lighting` / `fabric` / `goods`)。

例: `ops/products/pet-flower-lounge/`

**既存なら `product.md` を読んでから作業する。新規なら次で作る。**

### 3. 新規なら `product.md` を作成

テンプレートは `references/product_md_template.md`。必ず埋めるもの:

- Shopify product id / handle / 現在の status
- **内部タグ**(`docs/09` §5。カテゴリタグ + `tier-*` は必須)
- **原価記録**(仕入れ値・送料・想定売価・粗利)— 顧客に出さない内部情報
- 実測寸法・素材(仕入れ元資料の実値)
- 画像棚卸しの結果(§4)

### 3-2. 商品名を決める(**オーナー承認が要る**)

**`docs/09_navigation_taxonomy.md` §8 商品命名規則に従う。** ここは AI が単独で確定しない工程。

1. §8 の3行ルールで**候補を1〜3案つくる**
2. §8 の「使用済みの愛称」表で**重複していないか確認する**
3. §8 の命名時チェックを全項目通す(特に **多色バリアント商品に色名を入れない**、
   **tier に応じた愛称の有無**)
4. **候補をオーナーに提示し、承認を得てから `title` を確定する。** 勝手に確定しない
5. 確定したら **§8 の語彙表に愛称を追記する**(追記しないと次の商品で重複する)
6. `handle` は確定 title の英訳スラッグに合わせる

仕入れ元(CKB)の商品名は機械翻訳で、**他社商標・型番・誤訳・禁止表現を含んでいることが多い。**
そのまま短縮しただけの名前を採用しない。過去の実例は `ops/products/_classification_*.md` の
「命名で意図的に落とした表現」を参照。

### 4. `descriptionHtml` から画像URLを抽出し、商品メディアへ追加

仕入れ元の商品説明はたいてい `<img src="...">` の羅列。これを商品メディアに移す。

1. `descriptionHtml` から画像URLを順に抽出
2. **`altText` は「説明画像NN」**(NN は 01 から連番)で `productCreateMedia` に渡す
3. **URL を直接渡す。** 成功すれば mediaID が発行される
4. **mediaID の発行を必ず確認する。** 発行されない/`FAILED` になったものは
   **staged upload(`stagedUploadsCreate` → アップロード → `productCreateMedia`)へフォールバック**
5. 全件について「URL直渡しで成功 / staged でリカバリ / 未処理」を `product.md` に記録

> GraphQL は提示前に Shopify MCP の `validate_graphql_codeblocks` を通す(CLAUDE.md 必須ルール)。

### 4-2. 商品画像を読み取って、特徴・寸法・素材を抽出する

**仕入れ元の販促画像は寸法図と訴求文の宝庫。** ここを読めば「サイズ不明で書けない」の大半が解ける。
全体像は `docs/11_product_registration_workflow.md` §2。

1. `media { ... on MediaImage { id image { url } } }` で **URL と MediaImage ID** を取る
2. `curl` でローカルに落として1枚ずつ読む。**Shopify 側の画像には触らない(読むだけ)**
3. 拾うもの
   - **寸法図**: 「尺寸展示 / DISPLAY SIZE」「产品尺寸」「成品规格」の見出しを探す
   - **素材**: 「高密度回弹海绵」= 高密度ウレタン / 「碳素钢」= カーボンスチール / 「实木」は**そのまま訳さない**
   - **買うべき理由**: 「◯◯ 简单方便」のような、悩み → 解決の見出し
4. **手測り注記**(「产品为手工测量会存在稍许误差」)がある寸法は、日本語でも「約」+ 誤差注記を付ける

**絶対にやらないこと**

- 画像に書いていない寸法・素材を推定で埋める。**取れなければ「確認中」と書き、オーナーへの報告に回す**
- 画像の禁止表現を書き写す。実例: ランプ画像の**「护眼」「无蓝光」は健康に関わる未検証の主張**なので不採用。
  「不易变形」「不易生锈」等の耐久性主張も、数値の裏づけが無い限り採らない
- 1商品のメディアに**別SKUの寸法図が混ざっている**ことがある。商品名と構造が一致する図を採り、
  **食い違いは必ず報告する**(推測で選ばない)

### 5. 画像は最小限にする(2026-08-24 方針転換・D-080)

**サムネイル・商品画像・説明画像を作り込むワークフローは停止した。**
売上を立てて PDCA を回すのが先で、1商品に9〜13枚を作るのはこの段階では過剰。
旧ワークフローは `docs/_archive/2026-08_image-production-workflow/` に退避してある(参照しない)。

**いまやる画像作業は1種類だけ。**

#### 必須の画像が中国語のときだけ、日本語化する

対象は「**これが読めないと買えない**」画像に限る。判断基準:

| 日本語化する | しない |
|---|---|
| サイズ・寸法図 | 雰囲気カット・生活シーン |
| 素材や仕様の表 | 文字のない写真 |
| 使い方・取り付け方の説明 | 装飾的なキャッチコピー |
| 同梱物・セット内容 | 中国国内向けの販促(クーポン等) |

**それ以外は中国語のまま残してよい。** 全部やろうとしない。

#### 対象の洗い出し(先にこれをやる)

**説明画像は全数を目視する。途中で打ち切らない**(D-090。1回目はここで寸法図を取りこぼし、
「寸法図が1枚もない」とオーナーに誤報告した)。

- 全商品のメディアURLを一覧化する(`media` を全件ページング)
- **20枚ずつのコンタクトシート(5×4・1セル380px)に落として目視する。** Pillow は実行時に `pip install` できる
- **バイト数/画素で「図っぽい画像」を絞り込む方式は使わない。** 実測で仕様図が 0.24〜0.45bpp、
  写真と重なって分離できなかった

#### 手順(2026-08-24 に27枚で実地検証した手順)

1. Shopify の商品メディアから、対象画像の CDN URL を取る
2. `media_import_url` で Higgsfield に取り込み、`media_id` を得る
3. **元画像の縦横比を測り、いちばん近い aspect_ratio を選ぶ。** ここを外すと図が潰れる。
   `gpt_image_2` が取れるのは 1:1 / 4:3 / 3:4 / 16:9 / 9:16 / 3:2 / 2:3 だけ。
   PNG/JPEG のヘッダから幅高さを読めば PIL なしでも測れる
4. `gpt_image_2` / `resolution: 1k` / `quality: low` で生成(1枚 0.5 クレジット)
5. プロンプトは**日本語で、固有名詞まで指定する**。「中国語を日本語に」だけだと
   「茶几」「储物柜」のような語がそのまま残る。次の3つを必ず書く:
   - **訳語の指定**(例: 茶几→ローテーブル / 边几→サイドテーブル / 储物柜→ナイトテーブル /
     胡桃木色→ウォールナット色)
   - **維持するものの列挙**(レイアウト・文字の位置とサイズ・寸法の数値を全部書き出す・
     寸法線・家具の形と色・背景色・余白)
   - **「要素の追加・削除・移動は禁止」**
6. 出力を目視する。**崩れていたら諦めて元のまま残す**(作り直しに時間をかけない)
7. `productCreateMedia` で**日本語版を追加**する。`originalSource` に Higgsfield の
   結果URLをそのまま渡せば Shopify が取りに行く。**元画像は削除しない**
8. alt に「〇〇 寸法図(日本語版)」のように入れておく
9. **`productReorderMedia` でギャラリー写真の直後(4〜7枚目)へ移動する。**
   `productCreateMedia` は末尾に足すので、そのままだと写真20〜30枚の後ろに埋もれて
   「入っていない」と見える(D-091)。`moves: [{ id, newPosition }]` の
   **`newPosition` は 0始まりの文字列**

#### 生成しながら気づいたら直すもの

- **仕入れ元の透かし**(EPVANS・Taobao の URL・中国の社名ロゴ)は、
  プロンプトで「透かしは削除し、背景色で埋める」と指示すれば消える。
  他社の商標を自店の商品ページに出さない
- **中国国内向けの取引条件**(受け取り拒否の手順・当社カスタマーサービス・質保)が
  同じ画像に混ざっているときは、**その段落だけ日本語の正しい文面に差し替える**。
  レイアウトと行数を保ったまま書き換えれば崩れない
- 日本語化して初めて読める内容が、**登録済みの仕様表と食い違うことがある**
  (例: セル サイドボードは「组装发货免安装」=完成品なのに仕様表は「組み立て式」だった)。
  気づいたら仕様表のほうを直す

#### やらないこと

- サムネイルの生成
- 生活シーン・イメージカットの生成
- リファレンスシートを参照画像として渡すこと
- 商品ごとの画像棚卸し表の作成


### 7. 人間レビュー

**オーナーの確認なしに公開しない。** 提出時に必ず添えるもの:

- 画像棚卸し表(3軸評価の結果)
- 3タイプそれぞれの成果物と、何を「補正」で何を「生成」したかの明示
- 内部タグと `tier-*` の割り当て理由
- 未確認のまま残した仕様(寸法・素材で資料に無かったもの)

レビュー通過後にはじめて価格を確定し、ACTIVE にする。
