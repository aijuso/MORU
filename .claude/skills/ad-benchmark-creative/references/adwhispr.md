# AdWhispr Ads(MCP)の使い方

任意のブランドのMeta/TikTok広告を実データで取得・分析できるMCPコネクタ。
このスキルの分析ステップはすべてこのツールで行う。

## 主に使うツール

| ツール | 用途 | 引数の注意 |
|---|---|---|
| `get_my_brand` | MORU自身の登録確認 | `find_competitors` の前提 |
| `save_my_brand` | MORU自身を登録 | 外部サービスへの書き込み。オーナー確認後に実行 |
| `find_competitors` | 実際に広告を回している競合を発見 | **MORU登録が前提** |
| `search_brands` | 追跡中ブランドを名前で検索 | 未追跡なら「見つからない」と返る |
| `add_brand` | 新規ブランドの追跡開始 | **1日3件上限。削除しても戻らない** |
| `get_brand_stats` | 全体像(本数/最長稼働/出稿額/フック分布/フォーマット分布) | brandId |
| `get_brand_ads` | 個別広告の取得 | brandId + **`sortBy: longevity`** |
| `compare_brands` | 2〜3ブランドの横並び比較 | 領域をまたぐ比較に有効 |
| `research_tiktok_ads` | TikTok側の広告 | Meta側と型が違うことがある |

## ID の扱い(混同しやすい)

- **brandId** = UUID形式。`get_brand_ads` `get_brand_stats` など**ほとんどのツールで使う**
- **pageId** = 数値。**`add_brand` の結果に出てくるだけ**。他では使わない

追跡中ブランド(取得日 2026-08-28):

| ブランド | brandId | pageId |
|---|---|---|
| Kocol | `14a74159-4463-4160-bead-1a0b32d27ca8` | 145828888605304 |
| Desk Nest Cat Bed | `56f33a58-be4d-4aea-b0f3-b233ef9e3907` | 367212543468975 |

**このID表は追加のたびに更新すること。** 書いておかないと毎回 `search_brands` から引き直しになる。

## 取り込みの待ち時間

`add_brand` の直後はデータが空。**1〜3分かかる**(広告数が多いほど長い)。
サムネイルが先に入り、AI分類ラベルは数分遅れて埋まる。
すぐ `get_brand_stats` を叩くと分類が未完了のことがあるので、
「25 of 43 ads analyzed」のような表示が出たら、その旨をオーナーに伝えて待つか、
分析済みのサンプルに基づく数字であることを明記する。

## 数字の信頼度(重要)

| 指標 | 信頼度 | 扱い |
|---|---|---|
| **稼働日数(longevity)** | 高 | **唯一の勝ち指標。これで並べる** |
| 稼働本数 | 高 | 相手の本気度 |
| フック分布 / フォーマット分布 | 中 | 傾向は信頼できるが個別ラベルは誤りがある |
| 推定出稿額 | 低 | レンジが広い。桁感の参考のみ |
| **performance score** | **使わない** | 全広告で同一の既定値だった実績あり |

**フックの分類ラベルは必ずコピー本文で検証する。**
実例: Kocolは統計上12本が problem_agitation と分類されたが、
稼働日数上位の広告本文を読むと、本物の問題提起は1本だけだった
(「寝苦しい夜とは、もうサヨナラ。」)。
残りは「デスクや棚に置く小さめ収納から…」のような単なるカテゴリ紹介。

## 実売価格を見るときの注意

広告のリンク先が海外向けURL(`/en-us` 等)だと**価格がUSDに自動換算されている**。
Shopifyの多通貨機能によるもので、日本の実売価格ではない。
円価格が必要なときは日本向けURL(言語プレフィックスなし、または `/ja`)を見ること。

## 使えないこと

- 広告を出していないショップは拾えない(SEOやInstagramだけで売っている個人ECなど)。
  そこは `ops/research/sites.md` の画像逆引き経路で探す
- 実際の売上は分からない。売上が知りたい場合はKalodata等の別ソース

---

※ 数字を引用するときは、統計値(`get_brand_stats`)なのか実読で確認した値なのかを
必ず区別して書く。混ぜると後から検証できなくなる。
(実例: problem_agitation「12本」は統計ラベル、「本物は1本」は稼働日数上位の実読。
この区別を書かずに転記したことで「5本」という誤記が生まれ、D-160 後に訂正した)
