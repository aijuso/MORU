# 11. 商品登録ワークフロー(CKB → Shopify → フロント)

> 2026-08-23 新設。Tier1 5商品(フラワー キャットタワー / ソラ キャットハンモック /
> コーデュロイ フォールディングチェア / クラウド サイドテーブル / フラワーバッド テーブルランプ)で
> 実際に通した手順を、そのまま次回の手順書にしたもの。
> **実行の細部は `.claude/skills/product-registration/SKILL.md` が正。本書は全体像と落とし穴。**

---

## 0. 前提: 3つの層と、それぞれの「正」

| 層 | 何が入っているか | 正 |
|---|---|---|
| **CKB(仕入れ元)** | 中国語の商品名・機械翻訳・販促画像・原価 | 原価と**実寸**の一次情報 |
| **Shopify** | 商品名・タグ・価格・バリアント・**メタフィールド**・メディア | **公開されるデータの正** |
| **テーマ(フロント)** | メタフィールドをどう見せるか | `docs/03` + `templates/product.json` |

**原則: 文章と数値は Shopify に置き、テーマは表示だけを持つ。** テーマに文言を直書きしない。

---

## 1. 全体フロー

```
CKB取り込み
  ↓ ① 棚卸し(原状スナップショット)          → ops/products/_inventory_*.md
  ↓ ② 分類・命名(docs/09 §8・オーナー承認)   → title / handle / タグ / productType
  ↓ ③ 値付け(docs/10)                        → 全バリアントの price
  ↓ ④ バリアント整理                          → 受注生産・ギフト箱・管理値の除去
  ↓ ⑤ 画像の読み取り  ★本書の中心            → 特徴・寸法・素材の抽出
  ↓ ⑥ 説明文とメタフィールドの登録            → descriptionHtml / custom.* / global.*
  ↓ ⑦ コレクション所属と公開                  → タグ経由 + publishablePublish
  ↓ ⑧ フロントで描画確認                      → shopify theme dev
```

**②〜④を先に済ませること。** 刈られる商品に説明文を書くのは無駄になる(D-042 の順序)。

---

## 2. ⑤ 画像の読み取り(2026-08-23 に実行可能と確認)

仕入れ元の販促画像は、**寸法図と訴求文の宝庫**。ここを読めば「サイズ不明で書けない」問題の大半が解ける。

### 手順

1. `product { media { ... on MediaImage { id image { url } } } }` で URL と **MediaImage ID** を取る
2. `curl` でローカルへ落とす(**Shopify 側の画像には一切触らない。読むだけ**)
3. 1枚ずつ読み取り、次を拾う
   - **寸法図**(「尺寸展示 / DISPLAY SIZE」「产品尺寸」「成品规格」の見出し)
   - **素材**(「高密度回弹海绵」= 高密度ウレタン、「碳素钢」= カーボンスチール 等)
   - **買うべき理由**(「折叠收纳 简单方便」のような、悩み → 解決の見出し)
4. 特徴セクションに使う画像は **MediaImage ID で参照**する(URL ではない)

### 拾えた実例

| 商品 | 画像から取れた値 |
|---|---|
| コーデュロイ フォールディングチェア | 全高82 / 座面高47 / 座面41×44 / 背46×40 / 脚幅47cm、座面=高密度復元ウレタン、脚先=静音キャップ |
| フラワーバッド テーブルランプ | 高さ29.5 / シェード径16 / 台座径9cm、USB充電、天面タッチ、三色無段階調光 |
| ソラ キャットハンモック | 内寸41×31cm、耐荷重50lbs(≒22kg)、厚さ5cm以内の天板にクランプ、360度回転 |
| フラワー キャットタワー | 全体50×47×70cm、上段52×52×10cm、中段82×31cm、台座50×47×4cm |

### 読み取り時の禁止事項

- **画像に書いていないことを書かない。** 推定寸法・推定素材は入れない。取れなければ「確認中」と書き、報告に回す
- **画像の禁止表現は書き写さない。** 実例: フラワーバッド テーブルランプの画像には
  **「护眼(目に優しい)」「无蓝光(ブルーライトなし)」** があるが、**健康に関わる未検証の主張**なので不採用
- **「不易变形」「不易生锈」等の耐久性主張も採らない。** 数値の裏づけがない
- 手測り注記(「产品为手工测量会存在稍许误差」)がある寸法には、日本語でも **「約」と誤差注記**を付ける

## 3. ⑥ 1商品に登録する6点

| # | 置き場所 | 型 | フロントの表示位置 |
|---|---|---|---|
| 1 | `descriptionHtml` | HTML | アコーディオン「商品説明」 |
| 2 | `custom.catch_copy` | `multi_line_text_field` | ファーストビュー右の2行 |
| 3 | `custom.specs` | `rich_text_field` | アコーディオン「素材・サイズ」 |
| 4 | `custom.features` | `list.metaobject_reference` → `moru_feature` | 「この商品の特徴」帯 |
| 5 | `global.title_tag` | `string` | 検索結果のタイトル |
| 6 | `global.description_tag` | `string` | 検索結果の説明 |

### `moru_feature` メタオブジェクト

```
image   : file_reference  → gid://shopify/MediaImage/...
heading : single_line_text_field
body    : multi_line_text_field
```

`sections/moru-product-features.liquid` が左右交互に並べ、`01` から連番を振る。
**4〜5点が適量。** 6点以上は帯が長くなりすぎる。

### 分量(D-044)

| tier | descriptionHtml | features |
|---|---|---|
| `tier-hero` / `tier-core` | 5〜6段落。冒頭は docs/00 v0.2 §0-5 の Emotional 層から入る | 4〜5 |
| `tier-brand-builder` / `tier-aov` | リード文2〜3文(150〜250字)+ 仕様表 + 配送定型 | 3〜4 |

**全 tier 共通で、本文の最後に配送目安(約2〜3週間)を1文入れる。** アコーディオンにもあるが、
本文にも書くことで「隠していない」形にする(CLAUDE.md 絶対ルール5)。

## 4. 画像は最小限にする(2026-08-24 方針転換・D-080)

**サムネイル・商品画像・説明画像を作り込むワークフローは停止した。**
売上を立てて PDCA を回すのが先。旧ワークフローは
`docs/_archive/2026-08_image-production-workflow/` に退避してある(参照しない)。

**いまやる画像作業は「必須の中国語画像の日本語化」だけ。**

- 対象は「**これが読めないと買えない**」画像に限る:
  **寸法図 / 素材・仕様の表 / 使い方・取り付け方 / 同梱物**
- **対象外**: 雰囲気カット、生活シーン、文字のない写真、装飾的なキャッチコピー。
  **中国語のまま残してよい**
- Higgsfield(`gpt_image_2` / quality `low`)に**その画像1枚だけ**を渡し、
  「中国語を日本語にして、他は一切変えるな」とだけ指示する
- **崩れたら諦めて元のまま残す。** 作り直しに時間をかけない
- **元画像は削除しない。日本語版を追加する**

手順の詳細は商品登録スキル §5。

## 5. 落とし穴(実際に踏んだもの)

| # | 落とし穴 | 対処 |
|---|---|---|
| 1 | **`productOptionUpdate` の `optionValuesToUpdate` は1回10件まで。** 超えると超過分のオプション値と**バリアントが消える** | 10件ずつに分割し、前後で `variantsCount` を照合(D-051) |
| 2 | **API で作ったコレクションは販売チャネルに自動公開されない** | `publishablePublish` で公開し `resourcePublicationsCount` を確認(D-062) |
| 3 | **テーマエディタの設定はライブテーマにしか無い。** そのまま `theme push` するとロゴ・フォント・ヒーロー画像が消える | push 前に `theme pull` して差分を取り、エディタ管理の JSON はライブ側を取り込んでから自分の変更を載せ直す |
| 4 | **1商品のメディアに別SKUの寸法図が混ざっていることがある** | 商品名と構造が一致する図を採り、**食い違いは必ず報告**(推測で選ばない) |
| 5 | 商品タグを先に英字へ移すとコレクションから外れる | コレクション条件を先に新旧併記 → タグ移行 → 件数照合 → 旧条件削除(D-045) |
