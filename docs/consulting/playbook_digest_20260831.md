## 3. プレイブックと MORU ルールが衝突する箇所(docs 側が勝つ)

1. **商品画像の ChatGPT 生成(ステップ6・プレイブックの前提)** —
   MORU は **D-080 で画像作り込みワークフローを停止**済み。CLAUDE.md ルール9
   「形状の正は実物写真・登録済み画像を削除/差し替えしない」が生きている。
   生成画像の運用はいまは**広告クリエイティブ用に限る**(ルール10)。
   新商品(リブランド後)で画像方針をどうするかはオーナー判断事項(→ §4-3)。
2. **「最短翌日お届け」等の高速配送演出は使えない**(プレイブックには無いが、
   一般的なドロップシッピング手法の流用時に注意)。配送目安 2〜3週間の明示が CLAUDE.md ルール5。
3. **偽レビュー・偽割引・偽カウントダウン系の「刺さる広告の型」は借りない**(ルール6。
   ad-benchmark-creative スキルの「借りる/捨てる」の線引きが正)。

## 4. オーナーへの確認事項(このプレイブックを受けて)

1. **Winning Hunter を実際に導入するか。** 現環境には MCP が無く、AdWhispr で代替している。
   導入するなら Claude のコネクタ設定(オーナー側の操作)+クレジット残量の確認が必要(プレイブック ステップ1)。
   AdWhispr 継続でも Phase 1・11 の目的は満たせる。
2. **リブランド方向 A(束ね型)/ B(高単価尖り型)/ C(目標置き直し)の選択**(`ops/research/_rebrand_direction_20260830.md` §4)。
   これが決まらないとステップ2(リサーチ条件設計)に入れない。
3. **新商品の画像方針。** プレイブックは「海外画像の転用回避のため AI 生成」を前提とするが、
   MORU は D-080 で停止中。リブランド商品で再開するかどうか。
