## 0. なぜ変えたのか

docs/10 は「通常価格 = 着地原価 × 3.0」、docs/12 は「15%OFF 後も ×2.6 以上」を条件にしていた。
この2つは**数式として両立しない**。

```
×3.00 × 0.85 = ×2.55  <  2.6
```

ルールどおりに値付けした商品は、15%OFF を出した瞬間に必ず基準を割る。
2026-08-25 の監査で「要検討13商品」が出たのは商品の問題ではなく、**ルール同士の矛盾**だった。

さらに、固定倍率方式には次の問題がある。

- **×2.6 は粗利率 約61.5% 相当**で、EC の運用基準としてはかなり保守的
- 割引施策の良し悪しは粗利率だけでは決まらない。**AOV・注文あたり粗利額・CPA 許容額**を同時に見る必要がある
- 「注文0だから現在の高価格を据え置く」は**価格が正しい証拠ではない**。むしろ検証されていないだけ
- 割引を出すために通常価格を吊り上げるのは、**MORU がやらないと決めたこと**(docs/00 第11章・偽割引の禁止)

**したがって `×3.0` / `割引後 ×2.6` は参考指標として残すが、価格決定の Hard Gate にはしない。**

## 1. 基本思想

**価格は `原価 × 固定倍率` から決めない。**

決める順番はこれ。

| STEP | やること |
|---|---|
| 1 | **CKB 商品原価**を確認する |
| 2 | **推定着地原価**を確認する(landed 実測がなければ `CKB商品原価 + ship_est`) |
| 3 | **商品の役割**を決める(Summer Sale / Multi-buy / PAIR対象 / 販売保留・非掲載) |
| 4 | **お客様に実際にいくらで買ってほしいか**を先に決める(市場価格・商品価値・MORUの価格帯・CVR・AOV) |
| 5 | **プロモーションから通常価格を逆算**する |
| 6 | **採算を確認**する |

STEP 5 の例:

> Summer Sale 10% で **約 ¥9,000 で売りたい** → 通常価格を **¥9,980** にする。
> Multi-buy 商品なら、通常価格そのものを既に買いやすい価格にする。

## 2. 着地原価の扱い(D-112 を継続)

採用順は変えない。

1. **landed 実測**があればそれ
2. landed が無く `ckb_cost` があれば **`ckb_cost + ship_est`**(= 推定)
3. `ckb_cost` も無ければ **原価待ち**

> ⚠️ **`ship_est` は実送料ではない。**「価格設計用の送料概算」で、
> **小物 ¥800 / 中型 ¥1,750 / 大型 ¥3,500** の3バケットを置いているだけ。
> 国内送料・代行手数料・国際送料・関税の実測はまだ1件も取れていない。
>
> - **CKB 商品原価に送料概算を足して上書きしない。**生値は `ops/products/_ckb_costs.csv` に保つ
> - 推定した着地原価は `cost_source = 推定(ckb_cost + ship_est)` として出力に明示する
> - **未取得の原価を推測で埋めない。**旧原価や最小 Variant 原価からの類推も禁止(CLAUDE.md 絶対ルール15)

2026-08-25 時点: **223 / 257 Variant が推定、landed 実測は 0 件。**
つまり**いまの採算判断は ship_est の精度に丸ごと依存している。**実測を取ったら全件やり直す。

## 3. プロモーション構造

### A. Summer Sale — 原則 **10%OFF**

**対象**: 高単価 / 単品購入型の商品(家具・照明・ペット家具など)。

- 通常価格を不自然に吊り上げない。**通常価格を正常化したうえで 10% を載せる**
- 一律 15% にしない。低単価商品だけ 15% にするのも、**まとめ買い 15% との差が消えて階段が崩れる**ので避ける

### B. Multi-buy — **2点 10% / 3点以上 15%**

**対象**: 小物・クッション・ブランケットなど、複数買いが自然な商品。

- **Summer Sale には入れない**(施策の二重化を避ける)
- **通常価格そのものを、Summer Sale 商品のセール後価格くらいの「普段から買いやすい価格」にする**
- 1点 = 通常価格 / 2点 = 10%OFF / **3点以上はすべて 15%OFF**(4点・5点・6点以上も同じ)
- **同一 Product 内であれば、色・柄・Variant 違いを合算できる**
- **別 Product 同士は数量に合算しない**

### C. PAIR — **15%OFF**

指定した**別 Product 同士**を一緒に買ったときだけ適用する。

- **PAIR 限定販売にしない。**各商品は単品でも通常購入できる
- **PAIR 15% > Summer Sale 10%**
- **割引を加算して 25%OFF にしない。**Multi-buy と PAIR が同時に成立し得る場合も同じ
- **適用は「いちばん強い割引 1つだけ」**

#### 実装上の優先順位(Function 設計)

Shopify Function の `cart.lines.discounts.generate.run` は、1回の呼び出しで
カート全体を見て割引を組み立てる。優先順位はここで解決する。

```
1. PAIR 成立を先に判定する         (percentage 15)
2. 残りの行で Multi-buy を判定する  (2点 10 / 3点以上 15)
3. 残りの行に Summer Sale を当てる  (10)
4. 1商品につき割引は1つだけ。競合したら percentage の高い方を採用し、
   同率なら先に定義された方を採用する
5. 設定が読めない・壊れているときは何も割り引かない(fail-closed)
```

既存の `pair-set-discount` Function は 4 と 5 を既に満たしている
(`resolveWinners` が product ごとに最高 percentage を1つだけ残す)。
**Summer Sale・Multi-buy・PAIR を1つの Function に統合するか、
3つの Discount を Shopify 側の組み合わせ設定で排他にするかは Owner 決定事項。**

## 4. 価格評価のものさし

粗利率だけを見ない。**最低限これを並べて判断する。**

| 指標 | 定義 |
|---|---|
| 推定着地原価 | landed 実測 or `ckb_cost + ship_est` |
| 粗利額 | 売価 − 着地原価 |
| 粗利率 | 粗利額 ÷ 売価 |
| 決済手数料 | 売価 × 3.6%(**仮置き。実測なし**) |
| **返金引当** | **(売価 + 着地原価) × 引当率**(30日間安心保証。§8) |
| 限界利益 | 粗利額 − 決済手数料 − **返金引当** |
| BE ROAS | 売価 ÷ 限界利益 |
| CPA上限 | 限界利益 × 0.70 |
| AOV / CVR / 市場価格 | 数字だけでは出ない。Owner 判断 |

### スクリーニング目安(**Hard Gate ではない**)

| 目安 | 値 |
|---|---|
| 粗利率 | **55% 前後** |
| 限界利益(絶対額)・大型 | ¥5,000 |
| 限界利益(絶対額)・中型 | ¥2,500 |
| 限界利益(絶対額)・小物 | ¥800 |
| 参考指標(旧ルール) | 通常 ×3.0 / 割引後 ×2.6 |

> 粗利率(= (売価 − 着地原価) ÷ 売価)は返金引当を含まない定義なので、
> **引当率を変えても粗利率は動かない。引当の影響は限界利益・BE ROAS・CPA上限に出る。**

**絶対粗利額も重視する。**家具は 広告CPA・配送事故・返品・大型配送リスク が大きいため、
粗利率が高くても絶対額が薄いと1件の事故で吹き飛ぶ。

### 禁止する判断

- 🚫 **「倍率が高いから値下げない」** — ×3.0 は下限であって目標ではない
- 🚫 **「注文0だから据え置く」** — 注文0は現在価格が正しい証拠ではない
- 🚫 **割引を出すために通常価格を吊り上げる**(docs/00 第11章・偽割引)
- 🚫 **データが無い理由の捏造**(「在庫処分だから」「売れていないから」等)

## 5. Variant 価格の扱い

- Variant ごとに CKB 原価が違う商品を、**不自然に一律価格へ潰さない**
- 現在の価格階層(何段あるか)を維持したまま、レンジの端を新価格に合わせる
- **原価が高い Variant の価格が、原価が安い Variant より安くならないこと**(価格逆転チェック)
- **セット Variant(2脚セット等)は構造的二重割引に注意。**
  セット価格に更に施策割引が乗ると、単品×2 との差が意図より大きくなる

## 6. 送料無料しきい値との関係

送料無料は **¥7,700**(**割引後の subtotal** で判定)。

**設計時に必ずチェックする境界:**

- 通常価格は ¥7,700 以上なのに、**Summer Sale 10% 後に ¥7,700 を割る**商品
- Multi-buy の **2点 / 3点合計が、割引後に ¥7,700 を割る**組み合わせ
- **PAIR 合計が割引後に ¥7,700 を割る**組み合わせ

割った場合の選択肢は3つ。**どれを取るかは Owner 判断。**

1. 通常価格を上げてしきい値の上に戻す
2. しきい値そのものを見直す
3. そのまま出して、送料が乗ることを受け入れる

**Claude 側でしきい値を勝手に変えない。**

## 8. 30日間安心保証と返金引当(D-125)

顧客向けの正式方針:

- **「30日間安心保証」/「ご満足いただけない場合は返金いたします。」**
- 商品到着後 **30日以内**
- **原則返品不要で返金**
- 必要に応じて写真・動画を取得する
- 返金処理が完了するまでは商品を保管してもらう
- 返送が必要な場合のみ個別に案内する
- **初期不良・誤配送・配送破損は、顧客への返金とは切り離して THE CKB へ補償請求する**
- 不正利用・過度な反復利用は制限できる

### 採算への反映

**「返品引当 0%」は最終採算判定に使わない。**

```
返金引当額 = (売価 + 着地原価) × 引当率
限界利益   = 粗利額 − 決済手数料 − 返金引当額
```

**売価だけでなく着地原価も引当に入れる。**原則返品不要で返金するため、
返金が発生した注文では**売上も在庫も両方失う**からである。

| 引当率 | 位置づけ |
|---|---|
| 3% | 楽観シナリオ |
| **5%** | **Owner 判断用の中心値** |
| 8% | 保守シナリオ |

> ⚠️ **「MORU の返品率は 5% である」という主張ではない。**
> **実績が1件も無いための暫定引当。**初回の実績が出たら差し替える。
> 顧客向けの表示・広告に「返品率」を書かない。

出力: `ops/products/_refund_scenarios_20260825.csv`(3 / 5 / 8% を並記)

## 9. 送料無料 ¥7,700 と割引の関係(D-127)

**送料無料ラインは ¥7,700 のまま。下げない。**

**割引前 subtotal が ¥7,700 以上だった注文は、商品割引で ¥7,700 を割っても送料無料を維持する。**

そうしないと「割引を使ったほうが高くなる」注文が発生する。

```
割引前 ¥7,960 → 送料無料
      ↓ 2点 10%OFF (−¥796)
割引後 ¥7,164 → 送料 ¥870 が発生 = 実質 +¥74 の値上げ
```

実装方針は `ops/_promotion_architecture_20260825.md` §1。
**Shopify 標準の配送料金条件は割引後の金額で評価されるため、標準設定では実現できない。**
同じ Discount Function に配送ターゲットを足して、**割引前 subtotal で判定する。**

## 10. セット Variant の施策除外(D-126)

**セット価格に既にセットメリットが入っている Variant は、その上に施策割引を重ねない。**

第一例: **ハル ダイニングチェア 2脚セット**(1脚×2 比 −¥7,980)は **Summer Sale から除外**。
価格自体は変更しない。

**除外は Product 単位ではなく Variant 単位で指定する。**
