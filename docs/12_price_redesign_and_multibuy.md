## 0. 目的(2026-08-24 オーナー確定)

> **現行の ×3.0 機械値付けを全商品再監査し、
> 割引を前提にしなくても通常価格そのものに納得感がある価格へ再設計する。**

**「ストアで恒常30%OFFを実施している」という意味ではない。**
実査のとおり `compare_at_price` は全36商品 null で、**30%OFF の二重価格表示は存在しない。これを正とする。**
懸念されているのは**値付け倍率**であって、表示ではない。

その上で、**multi-buy 対象商品だけ**次を検討する。

| 購入点数 | 割引 | ねらい |
|---|---|---|
| 単品 | なし | 最も高い利益率 |
| 2点 | **10% OFF** | 利益率は少し下がるが、利益額 / AOV を増やす |
| 3点以上 | **15% OFF** | 利益率はさらに下がるが、注文あたり利益額を増やす |

MORU は安売り店ではない(**Pet-first, Interior-always. / Curated, Not General Store.**)。
割安感で買わせるのではなく、通常価格そのものに納得感を持たせる。

## 4. 現状の事実確認(2026-08-24 実査 + オーナー確認済み)

### 4-1. `compare_at_price` は全36商品すべて **null** — **これを正とする(オーナー確認済み)**

**ストア上に「30%OFF」の二重価格表示は存在しない。**
docs/10 §3 が取り消し線の二重価格を禁止しているため、そもそも作られていない。

**オーナー回答(2026-08-24): 懸念は広告クリエイティブの話ではなく、値付け倍率の話。**
「恒常30%OFFを実施している」という主張ではない。この論点は**解決済み**。監査は §0 の目的に沿って進める。

### 4-2. 現行の値付けルール(docs/10 v1)は「×3.0 + 20%クーポン」

```
通常価格 = (仕入れ値 + 送料概算) × 3.0 を ¥X,480 / ¥X,980 に切り上げ
検算     = クーポン20%適用後も 着地原価 × 2.4 を下回らないこと
```

現行の唯一の割引運用は **フラワーラウンジの発売記念クーポン 20%OFF(期間明示)**。
30%OFF の常設は設計にも実装にも存在しない。

### 4-3. 検算のしきい値が変わる

現行 docs/10 の検算は **20%OFF 後に ×2.4 以上**。
新設計では最大割引が **15%** になるので、検算式も置き換わる。**docs/10 §1 の改訂が必要。**

  フラワー フロアクッション ×5.36 / ボア ×4.55 / ガラスフラワー ×4.57)は、
  **「高すぎる」と即断してはいけない。** 棚卸しの仕入れ値が
  **最安 Variant のものしか記録されていない**可能性が高く、実際の原価はもっと高いかもしれない。
  → **Variant 別の CKB 原価を取り直すのが Phase A の最初の実作業。**
- `+¥500` 程度のズレは丸め処理の1段差なので実害はない。
- **15%OFF 後の倍率が ×2.6 を割る商品**(クラウド / コーデュロイ / ジオメトリック / ツインベル /
  ビス / コイル / ロンド / デュオ / ハル など)は、3点15%OFF の対象にすると
  スクリーニング水準を下回る。**もっとも、これらは家具で「3点まとめ買い」自体が起きにくい。**
  → **まとめ買い対象を `tier-aov` 中心に絞る根拠になる。**

#### 実装済み — 商品ページの数量アップセル UI

| 点数 | 実装内容 |
|---|---|
| 1点 | 通常 |
| 2点 | 1点目 / 2点目を**個別に選択可能**。Variant 違いを混在可能。**想定 10%OFF 価格を表示** |
| 3点以上 | 最初は3点。**`+1` で 4点・5点・6点… と追加可能**。各点の Variant を個別選択可能。**想定 15%OFF 価格を表示** |

対応済みの組み合わせ: アヒル + カエル / アヒル + カエル + ネズミ / アイボリー + ブルー / 同一 Variant 複数。

#### 実装済み — Cart Drawer / Cart Page

Shopify で**実際に Discount が適用された場合に**、次を表示する実装が入っている。

- 通常価格(取り消し線)/ 割引後価格 / **¥○○○ お得**
- 通常合計 / 割引合計 / 割引後合計

#### 現状

**Discount Function がまだ存在しないため、Cart / Checkout の実価格は通常価格のまま。**
商品ページの 10% / 15% 表示は**参考表示**であって、実計算ではない。

**Frontend 側で擬似的に価格を書き換えない**(ChatGPT 側の方針。Claude Code もこれを崩さない)。

#### Claude Code に求められていること

1. **Shopify Discount Function を作る**(§7-2。**Product ID 単位で数量合算**)
2. **有効化後に、Frontend Dev の表示価格と Cart / Checkout の実価格が一致するかを検証する**

ただし **Function の本番有効化・対象商品の確定・商品価格の変更は、
価格監査と Owner 承認のあと。**

### 7-2. Function の仕様

- Shopify Discount Function を使用
- target: **`cart.lines.discounts.generate.run`**
- 数量判定は **Variant ID 単位ではなく PRODUCT ID 単位**。
  **同じ Product に属する全 Variant の quantity を合算する**

| Product 合計数量 | 割引 |
|---|---|
| 1 | なし |
| 2 | **10% OFF** |
| 3以上 | **15% OFF** |

### 7-3. 判定例

| カート内容 | Product合計 | 結果 |
|---|---|---|
| アヒル×1 + カエル×1 | 2 | 両方 10%OFF |
| アヒル×1 + カエル×1 + ネズミ×1 | 3 | 全て 15%OFF |
| アヒル×2 + カエル×1 | 3 | 全数量 15%OFF |
| クッション アイボリー×1 + ブルー×1 | 2 | 両方 10%OFF |
| 4種類を1点ずつ | 4 | 全て 15%OFF |
| 5種類を1点ずつ | 5 | 全て 15%OFF |

### 7-4. カート変更時の再計算

- 3点 → 2点: 15% → **10%**
- 2点 → 1点: 10% → **解除**
- 4点 → 3点: **15%維持**
- Variant を削除・追加しても **Product 全体の数量で再計算する**

### 7-5. 対象商品の絞り込み

**全商品へ無条件適用しない。** Phase A の multi-buy eligible 判定に従う。

**判定方法(tag / metafield / other)を提案すること。**
既存の候補タグ: `tier-aov` / `cushion` / `object` / `textile`。

> 参考: 現行のタグ設計は `docs/09_navigation_taxonomy.md`。
> `tier-*` は階層、`cushion`/`object`/`textile` はカテゴリなので、
> **販促用の可否フラグをカテゴリタグに相乗りさせると後で困る**可能性がある。
> 専用の `multi-buy` タグか metafield を提案するほうが素直だが、**これも提案どまり。**

**Owner 承認前に tag / metafield を追加・変更しない。**

### 7-6. Discount Combination

現段階では **SALE / PAIR・SET DISCOUNT / その他 Product Discount との自動スタッキングを有効にしない。**
**Owner 承認なしに combination 設定を変更しない。**

### 7-7. 必須テスト

| # | ケース | 期待 |
|---|---|---|
| 1 | 同一 Variant 1点 | 0% |
| 2 | 同一 Variant 2点 | 10% |
| 3 | 同一 Variant 3点 | 15% |
| 4 | 別 Variant 2種類(計2点) | 10% |
| 5 | 別 Variant 3種類(計3点) | 15% |
| 6 | 別 Variant 4種類(計4点) | 15% |
| 7 | 別 Variant 5種類(計5点) | 15% |
| 8 | 同一 Variant×2 + 別 Variant×1 | 15% |
| 9 | 3点 → 2点 | 10% |
| 10 | 2点 → 1点 | 解除 |
| 11 | 対象 Product A×2 + 対象 Product B×1 | **A のみ10% / B は0%** |
| 12 | Variant ごとに価格が違う場合 | %計算が正しいこと |

**最終的に Product Page 参考価格 / Cart Drawer / Cart Page / Checkout が一致すること。**
※ Product Page は**参考表示**。**Cart / Checkout の Shopify 実計算が source of truth。**

不一致が出た場合、**Frontend の theme file を直して合わせにいかない。**
Function 側の誤りなら Function を直す。Frontend 側の誤りなら
**ChatGPT 側に渡す指摘としてまとめる**(再現手順・期待値・実測値)。
