## 0. オーナーの意図(原文の要約)

現状、一部または多くの商品が「**30%OFF した価格が本来売りたい価格**」になるような
高い通常価格になっている可能性がある。

MORU は今後、**恒常的な 30%OFF を前提にした価格アンカーをやめる**。

    「信頼できる通常価格」 + 「複数購入時だけ合理的に割引」

へ移行する。

| 購入点数 | 割引 | ねらい |
|---|---|---|
| 単品 | なし | 最も高い利益率 |
| 2点 | **10% OFF** | 利益率は少し下がるが、利益額 / AOV を増やす |
| 3点以上 | **15% OFF** | 利益率はさらに下がるが、注文あたり利益額を増やす |

MORU は安売り店ではない(**Pet-first, Interior-always. / Curated, Not General Store.**)。
割安感で買わせるのではなく、通常価格そのものに納得感を持たせる。

## 4. 【重要】現状の事実確認 — オーナーの前提とストアの実態がずれている

次セッションはここから読むこと。**2026-08-24 に Shopify を実査した結果:**

### 4-1. `compare_at_price` は全36商品すべて **null**

**ストア上に「30%OFF」の二重価格表示は存在しない。**
docs/10 §3 が取り消し線の二重価格を禁止しているため、そもそも作られていない。

つまりオーナーの言う「30%OFF した価格が本来売りたい価格」という状態は、
**compare_at ではなく値付けの倍率そのもの**に起因している可能性が高い。

### 4-2. 現行の値付けルール(docs/10 v1)は「×3.0 + 20%クーポン」

```
通常価格 = (仕入れ値 + 送料概算) × 3.0 を ¥X,480 / ¥X,980 に切り上げ
検算     = クーポン20%適用後も 着地原価 × 2.4 を下回らないこと
```

現行の唯一の割引運用は **フラワーラウンジの発売記念クーポン 20%OFF(期間明示)**。
30%OFF の常設は設計にも実装にも存在しない。

**→ Phase A の最初の作業は、「30%OFF前提」という認識がどこから来たのかをオーナーに確認すること。**
広告クリエイティブ側の話なのか、値付け倍率の話なのか、で作業が変わる。

### 4-3. 検算のしきい値が変わる

現行 docs/10 の検算は **20%OFF 後に ×2.4 以上**。
新設計では最大割引が **15%** になるので、検算式も置き換わる。**docs/10 §1 の改訂が必要。**

## 7. Phase B — 数量割引 Discount Function

### 7-1. Frontend は実装済み(触らない)

MORU Frontend Dev 側で、1点 / 2点 / 3点以上の UI がすでにある。

- 2点: 選択欄はちょうど2つ
- 3点以上: 最初は3つ。ユーザーが `+1` で 4点、5点、6点… と追加できる
- **Variant 違いを混在できる**(アヒル + カエル / アイボリー + ブルー / アヒル×2 + カエル×1 …)
- Cart Drawer / Cart Page は **Shopify が実際に適用した discount を表示する実装済み**

### 7-2. Function の仕様

- Shopify Discount Function を使用
- target: **`cart.lines.discounts.generate.run`**
- 数量判定は **Variant ID 単位ではなく PRODUCT ID 単位**。
  **同じ Product に属する全 Variant の quantity を合算する**

| Product 合計数量 | 割引 |
|---|---|
| 1 | なし |
| 2 | **10% OFF** |
| 3以上 | **15% OFF** |

### 7-3. 判定例

| カート内容 | Product合計 | 結果 |
|---|---|---|
| アヒル×1 + カエル×1 | 2 | 両方 10%OFF |
| アヒル×1 + カエル×1 + ネズミ×1 | 3 | 全て 15%OFF |
| アヒル×2 + カエル×1 | 3 | 全数量 15%OFF |
| クッション アイボリー×1 + ブルー×1 | 2 | 両方 10%OFF |
| 4種類を1点ずつ | 4 | 全て 15%OFF |
| 5種類を1点ずつ | 5 | 全て 15%OFF |

### 7-4. カート変更時の再計算

- 3点 → 2点: 15% → **10%**
- 2点 → 1点: 10% → **解除**
- 4点 → 3点: **15%維持**
- Variant を削除・追加しても **Product 全体の数量で再計算する**

### 7-5. 対象商品の絞り込み

**全商品へ無条件適用しない。** Phase A の multi-buy eligible 判定に従う。

**判定方法(tag / metafield / other)を提案すること。**
既存の候補タグ: `tier-aov` / `cushion` / `object` / `textile`。

> 参考: 現行のタグ設計は `docs/09_navigation_taxonomy.md`。
> `tier-*` は階層、`cushion`/`object`/`textile` はカテゴリなので、
> **販促用の可否フラグをカテゴリタグに相乗りさせると後で困る**可能性がある。
> 専用の `multi-buy` タグか metafield を提案するほうが素直だが、**これも提案どまり。**

**Owner 承認前に tag / metafield を追加・変更しない。**

### 7-6. Discount Combination

現段階では **SALE / PAIR・SET DISCOUNT / その他 Product Discount との自動スタッキングを有効にしない。**
**Owner 承認なしに combination 設定を変更しない。**

| 9 | 3点 → 2点 | 10% |

**最終的に Product Page 参考価格 / Cart Drawer / Cart Page / Checkout が一致すること。**
