- 割引の得が **−¥1,098 と小さい**ため、**PAIR にしても取りこぼす利益がいちばん少ない**
- 両方 Summer Sale 商品なので、**PAIR に入らなくても単品で売れる導線がある**

### 🚩 P-F だけ2つ問題がある

1. **PAIR後 ¥7,191 で送料無料 ¥7,700 を割る**(§3)
2. **限界利益 ¥3,861 は7組中最小**、かつ得が **−¥771** しかない。
   顧客から見た「一緒に買う理由」が弱く、割引に見合う束ね効果が出にくい

**P-F は後回し、または通常価格の見直し後に再検討を推奨。**

### PAIR とほかの施策の重複

**バルーンドッグ(MB)+ ツインベル(SALE)** のように、
**Multi-buy 商品と Summer Sale 商品をまたぐ PAIR** が P-F と P-6 以外にもある。
docs/13 §3-C の優先順位(**PAIR 15% > Summer Sale 10% > Multi-buy、加算しない、1商品1割引**)で
解決する設計。**既存の `pair-set-discount` Function は「1商品につき最高 percentage を1つだけ」を
既に実装している**ので、統合 Function にするか Shopify の組み合わせ設定で排他にするかを決めれば済む。

# 追補(2026-08-25 その2)— 30日間安心保証・送料無料境界・ハル Sale 除外

## A. 返金引当 3 / 5 / 8% の再計算(D-125)

```
返金引当額 = (売価 + 着地原価) × 引当率
限界利益   = 粗利額 − 決済手数料(3.6%) − 返金引当額
```

**売価だけでなく着地原価も引当に入れている。**原則返品不要で返金するため、
返金が起きた注文では**売上も在庫も両方失う**から。

評価は **その商品に実際に適用され得るいちばん深い割引**(211 Variant)で行った。

| 引当率 | 粗利率 | 限界利益 | 限界利益ゼロ以下 | 粗利率50%未満 | 粗利率55%未満 |
|---|---|---|---|---|---|
| 3% | 55.6 〜 73.1% | ¥1,208 〜 ¥48,264 | **0** | **0** | **0** |
| **5%(中心値)** | 55.6 〜 73.1% | **¥1,135 〜 ¥45,770** | **0** | **0** | **0** |
| 8% | 55.6 〜 73.1% | ¥1,025 〜 ¥42,028 | **0** | **0** | **0** |

**粗利率が3行とも同じなのは誤りではない。**粗利率 = (売価 − 着地原価) ÷ 売価 は
引当を含まない定義なので、**引当の影響は限界利益・BE ROAS・CPA上限に出る。**

**引当 8% でも赤字 Variant はゼロ。広告商品として成立する。**
最も薄いのは フェイクファー 100×150cm(3点以上15%)で、
**引当5%: 限界利益 ¥1,135 / BE ROAS 2.23 / CPA上限 ¥794。**

## C. 送料無料境界7件の最善の解決(D-127 / D-128)

**Owner 決定どおり ¥7,700 は維持。¥6,980 に下げない。**

**推奨: 既存の Discount Function に配送ターゲットを追加し、
「割引前 subtotal が ¥7,700 以上なら、割引後に下回っても送料無料」にする。**

| 案 | 判定 |
|---|---|
| Shopify 標準の配送料金条件 | ❌ **不可。標準条件は割引後の金額で評価される** |

> ⚠️ 配送ターゲット実行時に `line.cost.amountPerQuantity` が商品割引の前か後かは
> **ドキュメントから断定できなかった。実装後に DEV で1回テスト注文を通して確認する。**
> 後だった場合は、割引率が設定 metafield にあるので足し戻して復元できる。

## F. Promotion Function 統合案(D-128)

**現状の問題**: `multi-buy-discount` と `pair-set-discount` が**別々の Function**として
商品割引を出すため、**Shopify の組み合わせ設定次第で加算され得る。**
Owner 方針(加算禁止・1商品1割引)をコードで保証できていない。

**`moru-promotions-discount` 1本に統合する:**

```
cart.lines.discounts.generate.run
  1. PAIR       → percentage 15 の候補
  2. Multi-buy  → 同一 Product 内の合計数量で 2点=10 / 3点以上=15(別 Product は合算しない)
  3. Sale       → percentage 10
  4. 1商品につき候補は1つだけ。高い percentage が勝ち、同率なら定義順(PAIR > MB > Sale)
  5. 設定が読めない → operations 空(fail-closed)

cart.delivery-options.discounts.generate.run
  6. 割引前 subtotal ≥ ¥7,700 → 配送 100%OFF
```

**手順4は既存 `pair-set-discount` の `resolveWinners` が実装済み。**統合は新規発明ではなく合流。
設定 metafield に `freeShippingThreshold` / `pairs` / `multiBuy` / `sale`(+ `excludedVariantIds`)。
**固定 Product ID はハードコードしない。**

**移行**: 新拡張を deploy(既存2本は残す)→ 新 Function で Discount を1つ作る →
動作確認 → 旧2本を削除して再 deploy。**旧2本の Discount は未作成なので顧客影響は無い。**
