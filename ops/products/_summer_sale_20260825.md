# SUMMER SALE 候補 と SALE collection 案(2026-08-25)

> **⛔ 何も適用していない。**商品の price / compare_at_price / tags / status を1件も変えていない。
> collection への商品追加も rule 変更もしていない。ここにあるのは提案だけ。
>
> 割引率は **10%** で試算している。**確定値ではない**(CKB 原価監査の前なので確定できない)。
> **`compare_at_price` は作らない。**実際の Shopify Automatic Discount で出す前提。

## 選定の根拠について

**このストアには注文が1件も無い**(`ordersCount` = 0・実査)。
したがって「売れていない」「在庫処分」「人気商品」といった**販売実績を根拠にした理由は
1つも書いていない。書けるデータが存在しない。**

代わりに使った軸は、Owner 指示のとおり次の5つ:

1. **季節感** — 今の季節に使い方が説明できるか
2. **見せやすさ** — 写真・広告クリエイティブとして成立するか
3. **広告流入後の回遊** — 入口になり、次の商品へ繋がるか
4. **買いやすい価格帯** — 初回購入のハードルを越えるか
5. **カテゴリのバランス** — SALE 一覧が特定カテゴリに偏らないか

### Hero(MORU フラワーラウンジ)を SALE に入れるか — **入れないことを推奨**

理由:

- `tier-hero` は **ブランドの価格アンカー**。全商品の値ごろ感がこの1台を基準に読まれる
- **広告のランディング先そのもの**(ホームのヒーロー3枚すべてがこの商品へリンクしている)。
  流入直後に値引き表示が出ると、通常価格の側の信頼が落ちる
- **ローンチ時点で在庫があるのはこの商品だけ**(`totalInventory` = 10。他は全て0)。
  値引きで初動を作る必要が最も薄い

入れる場合は、その理由を Owner が明示した上で判断してほしい。

## SALE collection 案

**現状:** handle `sale` / タイトル「セール」/ **スマートコレクション(rule: TAG = `sale`)/ 0商品**。
ホームの CTA バナーが `/collections/sale#promo` にリンクしているため、
**いま押すと空のページに着く**(ローンチ阻害 — `ops/_launch_blockers_20260825.md` 参照)。

### 案A(推奨)— 既存の `sale` を「常設の SALE 入口」として使う

| 項目 | 値 |
|---|---|
| handle | **`sale`(既存のまま)** |
| title | セール |
| description | 「いま割引価格でお求めいただけるアイテムです。価格はカートで自動的に反映されます。」 |
| 対象 Product | 上記候補のうち Owner が承認したもの |
| manual / smart | **smart(既存 rule のまま: TAG = `sale`)** |
| 使用するタグ | **`sale`**(既存 rule に合わせる)+ 集計用に **`sale-summer-2026`** を併記 |
| Discount の当て方 | Automatic Discount の対象を **collection `sale`** にする |

**なぜ smart か:** タグ1つで「コレクションの中身」と「割引の対象」が**同時に**変わる。
manual にすると、コレクションに入れたのに割引が当たらない(またはその逆)というズレが起きうる。
**タグを外し忘れて割引だけ残る**という事故も smart なら起きない。

**なぜ handle を変えないか:** ホームの CTA バナーが既に `/collections/sale` を指している。
handle を変えると **Frontend の修正が必要になる**(ChatGPT 側の作業が増える)。

### 案B — キャンペーンごとに専用コレクションを作る

| 項目 | 値 |
|---|---|
| handle | `summer-sale-2026` |
| title | SUMMER SALE |
| description | 「2026年夏のセール対象アイテム。」 |
| manual / smart | smart(rule: TAG = `sale-summer-2026`) |
| 使用するタグ | `sale-summer-2026` |

**利点:** キャンペーンの履歴が残り、次回以降と混ざらない。
**欠点:** **CTA バナーのリンク変更が要る**(Frontend = ChatGPT 側)。
`/collections/sale` を残すなら**2つのコレクションを維持する**ことになる。

### 推奨

**ローンチは案A。**Frontend に手を入れずに済み、空ページの阻害要因が消える。
キャンペーンを重ねる段になったら案Bへ移す。

### タグ設計との整合(docs/09)

`sale` は **カテゴリでも階層でもない販促フラグ**。docs/09 の内部タグ体系
(`tier-*` = 階層 / `cushion`・`object`・`table` = カテゴリ)とは別の軸なので、
**カテゴリタグに相乗りさせない**という D-098 の原則と矛盾しない。

> ⚠️ ただし **multi-buy の対象判定は metafield(`custom.multi_buy_eligible`)** で、
> **SALE の対象判定はタグ(`sale`)** という**二重の方式**になる。
> 理由は違う: multi-buy は Function の input から読む必要があるので metafield、
> SALE は Shopify 標準の Automatic Discount がコレクションを直接指定できるのでタグでよい。
> **この使い分けは docs に記録した(D-101)。**
