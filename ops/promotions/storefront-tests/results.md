## 🔴 未検証: 送料無料の維持

**商品割引はすべて実機で確認できたが、送料はまだ測れていない。**

| 試したこと | 結果 |
|---|---|
| `/cart.js` | **送料を含まない**(商品割引だけ) |
| `/cart/shipping_rates.json` | **¥870 を返すが、これは旧エンドポイントで Discount Function を通さない**。判定材料にならない |
| `/checkout` へ HTTP アクセス | **403**(ブラウザ以外を弾く) |
| Chromium / Playwright | このサンドボックスの外向きプロキシを通れない(`ERR_CONNECTION_RESET`) |

したがって **A-1 の「送料 ¥870 が復活しないか」はまだ確認できていない。**
これは今回いちばん重要な確認項目なので、**PASS とは書かない。**

残る手段は2つ:

1. **Storefront Cart API**(`deliveryGroups` を読む)
   → **storefront access token の発行が要る。**承認リストに無い新規クレデンシャルなので**勝手に作らない**
2. **Owner がブラウザで1回だけ checkout 直前まで進める**
   カート: フェイクファー 150×200 を **2点**(小計 ¥7,960 → 割引後 ¥7,164)
   **配送料の欄が ¥0 / 送料無料 になっていれば OK。¥870 が出たら NG。**

⚠️ NG だった場合の原因はほぼ1つに絞れている:
配送ターゲットが読む `line.cost.amountPerQuantity` が**商品割引の適用後**の値だったケース。
その場合は割引率が設定にあるので足し戻して復元できる(`ops/_promotion_architecture_20260825.md` §1)。
